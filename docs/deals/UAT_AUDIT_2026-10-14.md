## Defects reproduced and corrected

1. A name-only draft can be created, but reopening it and pressing **Save draft**
   fails in live UAT with `"items" must contain at least 1 items`. The editor sends
   all fields, whereas previous API coverage only edited its description. Draft
   updates now permit empty contents. Published deals still reject empty contents
   with a 400 response and retain their saved values.
2. The admin API displays an unset draft price as zero. Reopening the draft filled
   the price input with `0`, and the next save sent an invalid zero price. The
   editor now keeps that input blank and sends `null`. Draft updates permit an
   unset price; publication still requires valid savings and a positive price.

The new tests cover repeated empty-draft saves, removing every component,
clearing a previously entered price, rebuilding and publishing, private draft
visibility, and unchanged database records after rejected published edits.
Playwright runs the entire workflow at 1440px and 390px against the real admin,
Express API and isolated MongoDB.

## Limits and follow-up

The fixes are committed for review; they are not deployed to UAT. Database and
payment assertions above ran against isolated CI databases, not the live UAT
database. Completing a live UAT order-to-database trace still requires an
identified customer test account and a UAT database/log access route.

The release manifest `deployment/uat/portal.json` still points at a storefront
commit predating Deals. The deals tests now use the actual UAT branch snapshot;
the release manifest itself is unchanged and needs alignment before promoting
the companion feature. A passing feature run is not production release approval.
